  LumiNation Simulator — Three.js FPV (Citizen View) Implementation Roadmap
================================================================================
Date: 2026-05-18
Author: Claude Code
Goal: Replace the Canvas 2D drawFPV() function with a fully 3D WebGL scene
      using Three.js, while keeping ALL existing simulation logic intact.

================================================================================
  WHY THREE.JS?
================================================================================
The current Canvas 2D FPV uses manual perspective projection (projX/projY helpers).
Every object (building, lamp pole, light cone) is hand-drawn with 2D ctx calls
that approximate 3D. This gives a flat, blocky, "cyberpunk 80s" look because:
  - No real depth testing (painter's algorithm breaks at oblique views)
  - No real lighting (gradients fake light; they don't react to geometry)
  - No atmospheric depth (fogging is just opacity tricks)
  - No shadows, no ambient occlusion, no physical material response

Three.js gives us:
  - True WebGL perspective + depth buffer (no painter's algorithm needed)
  - Real PointLights / SpotLights that cast actual light on road + building surfaces
  - THREE.FogExp2 for organic depth haze (distant lamps glow realistically)
  - MeshStandardMaterial with PBR roughness/metalness
  - True 3D geometry (BoxGeometry buildings, CylinderGeometry poles)

================================================================================
  CONSTRAINT: ALL SIMULATION LOGIC MUST BE PRESERVED
================================================================================
These values flow from CitySimulator.tsx refs into the FPV component as props:
  - lampsRef      → the real lamp array (brightness, position)
  - trackedRef    → the pedestrian the camera follows
  - lookaheadRef  → slider 0–5 (seconds) → controls corridor length
  - baselineRef   → slider 0.15–1.0 → controls dim brightness floor
  - agentsRef     → all agents (for spawning a ped if none exists)

The corridor logic in FPV is:
  - Virtual streetlights scroll toward camera at walker speed
  - If lamp.z < lookaheadZ → brightness = MAX_VISUAL_BRI (0.85)
  - If lamp.z > lookaheadZ → fade from MAX_VISUAL_BRI down to baseline × MAX_VISUAL_BRI
  - This must map 1:1 into Three.js PointLight.intensity

  STEP 1 — ARCHITECTURE OVERVIEW
================================================================================
New file: src/FPV3D.tsx

  - Runs its own requestAnimationFrame loop (independent of Canvas loop)
  - Receives simulation refs as props

  - The existing canvas loop continues but drawFPV(ctx) is never called (unused)
  - Pass refs as props: lampsRef, trackedRef, lookaheadRef, baselineRef, agentsRef

Props interface for FPV3D:

================================================================================
  STEP 2 — THREE.JS SCENE SETUP
================================================================================
Camera:
  - PerspectiveCamera(75, aspect, 0.1, 300)
  - Position: (0, 1.7, 0)        ← eye level 1.7m
  - lookAt: (0, 1.7, -100)       ← looking straight down street
  - Head-bob: camera.position.y = 1.7 + sin(stride * π) * 0.04

Renderer:
  - WebGLRenderer({ antialias: true, alpha: false })
  - setPixelRatio(devicePixelRatio)
  - setSize(width, height)
  - shadowMap.enabled = true
  - shadowMap.type = THREE.PCFSoftShadowMap
  - toneMapping = THREE.ReinhardToneMapping
  - toneMappingExposure = 1.2
  - Background color: 0x020205

Scene:
  - THREE.Scene()
  - scene.background = new THREE.Color(0x020205)
  - scene.fog = new THREE.FogExp2(0x020a1a, 0.018)
    (exponential fog: starts subtle, builds quickly at 50–100m depth)

Ambient light:
  - THREE.AmbientLight(0x08080f, 0.4)   ← very dim blue-black fill

Materials:

    glows in darkness without needing a separate light.

Position:
  - Left buildings: x = -9 (center of 10m wide block, edge at -4 curb)
  - Right buildings: x = +9
  - Y offset: height/2 (so base sits on y=0)
  - Z: starts at -7.5, -22.5, -37.5, ... (7.5 + i*15)

Recycling logic:
  Each frame: if building.position.z > camera.position.z + 5:
    → wrap to camera.position.z - (maxDepth)
    → assign new seeded height/material

================================================================================
  STEP 5 — STREETLIGHT POOL (INFINITE SCROLLING + CORRIDOR BRIGHTNESS)
================================================================================
Pool size: 24 lamps (12 left + 12 right)
Lamp spacing: 25m (Z direction) — staggered: left at z=0, 50, 100... right at 25, 75, 125...

Per lamp group (Three.js Group):
  a) Pole — CylinderGeometry(0.04, 0.06, 6, 6)
     Material: MeshStandardMaterial({ color: 0x8c8ca0, roughness: 0.6 })
     Position: (lampX, 3, z)    ← lampX = ±4.1 (sidewalk edge)

  b) Arm — BoxGeometry(1.2, 0.06, 0.06)
     Position: angled from pole top toward road center
     For left lamp: arm extends +0.6 toward street (x = lampX + 0.6)

  c) Fixture/hood — CylinderGeometry(0.18, 0.25, 0.15, 8)
     Inverted cone shape, at end of arm, y=6.0
     Material: MeshStandardMaterial({ color: 0x4a4a5a })

  d) Bulb — SphereGeometry(0.08, 8, 6)
     MeshStandardMaterial({ emissive: 0xffeebb, emissiveIntensity: driven by bri })
     Position: inside fixture

  e) PointLight — color 0xffd060, distance 20, decay 2
     Position: at fixture tip, (lampX ± 0.6, 6.0, z)
     intensity: computed from corridor logic (see Step 6)
     castShadow = true (only for close lamps, z < 20)

  f) Ground pool — CircleGeometry(3, 16) horizontal at y=0.01
     MeshBasicMaterial with emissive amber, transparent, opacity driven by bri
     Emulates the pool of light on the road

Recycling: same pattern as buildings. If lamp.z > camera.z + 5 → wrap to far end

================================================================================
  STEP 6 — CORRIDOR BRIGHTNESS LOGIC (MAPS FROM SIMULATION TO THREE.JS)
================================================================================
This must match the existing drawFPV logic exactly:

  const lookaheadZ = lookaheadRef.current * 8.0
    (8.0 scale: 1 second of lookahead ≈ 8m of corridor in world units)

  For each virtual lamp at world Z position zWorld:
    const zFromCamera = Math.abs(zWorld - camera.position.z)
    const lookaheadDist = Math.max(12, lookaheadZ)
    const fadeLength = 10  // meters of fade zone

    let bri
    if (zFromCamera <= lookaheadDist) {
      bri = MAX_VISUAL_BRI  // 0.85 — fully lit corridor
    } else {
      const distPast = zFromCamera - lookaheadDist
      const fadeFactor = Math.min(1, distPast / fadeLength)
      const baseBri = baselineRef.current * MAX_VISUAL_BRI
      bri = MAX_VISUAL_BRI * (1 - fadeFactor) + baseBri * fadeFactor
    }

Map bri → Three.js values:
  - PointLight.intensity = bri * 40       (0 → 34 range)
  - bulb.material.emissiveIntensity = bri * 3
  - groundPool.material.opacity = bri * 0.6
  - fixture emissive color alpha: bri

  STEP 7 — STARS + SKY

Stars:

  - Placed randomly in upper hemisphere at r=200
  - y > 20 only (above horizon)
  - MeshBasicMaterial({ color: 0xffffff }), opacity random 0.3–1.0

Horizon glow (city light pollution):

  - MeshBasicMaterial({ color: 0x0a1020 }) — very faint blue
  - Adds depth and separates sky from road plane

================================================================================
  STEP 8 — CAMERA ANIMATION (HEAD-BOB + FORWARD MOVEMENT)
================================================================================
The virtual camera is always at (0, 1.7, z) looking forward.
z doesn't actually move — instead, buildings and lamps scroll toward z=0.

But: stride animation drives head-bob:
  camera.position.y = 1.7 + Math.sin(stridePhase * Math.PI * 2) * 0.04
  camera.position.x = Math.sin(stridePhase * Math.PI) * 0.015  // slight sway

stridePhase: updated each frame by += (deltaTime * PED_SPEED / strideLength)
   PED_SPEED = 1.4 m/s
   strideLength = 0.75m
